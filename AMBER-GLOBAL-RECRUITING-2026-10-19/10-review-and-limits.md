# The independent code review, what it found, and the limits that remain

Written 19 Oct 2026 (Pacific). After the recruiting lane was built and tested, a second Claude session that had not written the code was asked to attack it: to read it as a hostile page, a careless owner and a scripted client would, and to run what it claimed. It reviewed commit `edaa2ef4`, re-ran 229 tests on a frozen copy (all passed, type check and linter clean), and reported 15 findings. Its report is model output, not a human audit and not a security certification; its findings were each reproduced or marked plausible. This file says what was done about each. Everything marked **fixed** has a test in `src/lib/recruiting/__tests__/review-fixes.test.ts` (or in `robots-wildcards.test.ts`, `fuzz.test.ts`, `text-readers.test.ts`, `lane.test.ts`).

## What was found, and what was done

| # | Severity | Finding | Status |
|---|---|---|---|
| 1 | High | One business under several records (an office in each city) got a second first message after an opt-out on the first; the opt-out matched only the exact address or site; the reply reader missed 9 of 13 opt-outs | **Fixed.** Records on one website are one business for opt-outs, history and the queue. `www.`, subdomains, trailing dots, schemes and plus-addressing no longer defeat a match. The button carries the site and address. The reply reader catches the common phrasings and is read again over the whole log |
| 2 | High | Past 20,000 logged actions the newest ones were silently not read (a suppress returned success and did nothing) | **Fixed.** A full record refuses the next action with a plain message; the page warns at 90%; ids sort in write order so two actions in one millisecond fold in the order written |
| 3a | High | A 46-byte `Disallow` rule with several `*` made a company-site check take seconds to minutes on the worker, which is one process for every lane | **Fixed** in the shared `research/robots.ts`: a plain wildcard matcher with no backtracking, a cap on rule and path length, and a cap on the size of a robots.txt that is read. A test compares it with the old matcher on 20,000 random rules and paths (same answers) and checks the hostile rule is answered at once |
| 3b | High | Many `<script>` tags and a closing tag without `>` made the page reader quadratic (10 s at 400 KB) | **Fixed.** Once a closing tag is found to have no `>` after it, no later one is searched for. The fuzz test now has this shape |
| 4 | Medium | Claims written under the `--` line (a client list, "guaranteed") were never read | **Fixed.** The footer is read for stock phrases, claims and false closeness; the sender's own name, business and address are taken out first |
| 5 | Medium | A note for a contact form skipped every footer and address rule | **Fixed.** Same footer rules as email |
| 6 | Medium | Correcting a company's website kept the old mailbox | **Fixed.** The gate blocks an address that is not on the company's site as it stands; the worker drops the old mailbox and reads the new site |
| 7 | Medium | Markdown escaping let a pipe, a link, an image or an address in a company name or title break the table or become a live link | **Fixed.** Every character Markdown reads as markup is escaped; links are only ever the two web addresses the list itself prints. Tested by reading the output with a Markdown (GFM) parser: eight cells, no image, no raw markup, two links. (CSV was already complete) |
| 8 | Medium | A person's name and phone number could be stored as a role title; XML fields were uncapped (a 3.9 MB title made a 7.8 MB document) | **Fixed in part.** Addresses and phone numbers, and the name written next to one, are cut; every text field is capped. **Remains:** a name written alone in a public title cannot be told from a role, so the claim is "no person is sought out, listed or profiled", not "no name can ever pass through" |
| 9 | Medium | A company's "no cold emails", "no recruiters or agencies" and similar notices were missed; employers that said so were still in the list | **Fixed.** Wider set of phrasings (tested against sentences that merely contain the words); those employers are left out of the list |
| 10 | Medium | Overstatements: a note offered "ten or so employers in healthcare" with none; "Clients won: 1" after one click; the same payment entered twice counted twice; "found on your careers page" for any address with `jobs` in its host | **Fixed.** A note names an area only when there are rows in it, gives the exact count when small, and is not written at all when fewer than two rows exist. Clients are counted from signed agreements and counted payments on the ledger, once per business; the click is shown separately as "marked as won". One reference is one payment. The page type comes from the path only |
| 11 | Low | One damaged row in the log (a good envelope, a bad payload) made the page, the API and the worker fail | **Fixed.** Each row is checked before it is applied; a bad one is left out, counted, and shown on the page |
| 12 | Low | The follow-up clock started at UTC midnight (as little as 6 days after a late send); an old typed date made a follow-up ready at once | **Fixed.** Whole days from the end of the day typed; a date cannot be earlier than the day before approval |
| 13 | Low | Ties in time broken by a random id (an approval and an edit in one millisecond); withdrawing and re-approving the process, or changing a setting and back, revived old approvals unseen; a sent message could be rejected through the API | **Fixed** |
| 14 | Low | A subject accepted a line break; `add-board` accepted `constructor`; `?minDays=abc` dropped the 45-day floor; the request body was read before its size was checked | **Fixed** (the body is read up to the limit and no further) |
| 15 | Plausible only | In shared code used by other lanes: `safeFetch` looks up a host again after checking it; robots.txt is not re-checked on a redirect target; robots.txt fetches are outside the 110-request budget; the robots body had no cap | The cap is **fixed** (see 3a). The other three are **left as they are and documented here**, below |

## Limits that remain

1. **Three behaviours of code shared with other Amber lanes are unchanged:** the address check in `src/lib/api-v1/url-guard.ts` resolves a host and then the request resolves it again (a hostile DNS answer could differ between the two); the robots.txt rule of a company site is not checked again on the page a redirect leads to; and the robots.txt requests are not counted against the lane's 110-request budget. They were left alone because they belong to code that other lanes run in production, nothing could be run against a live host from the build environment, and a change there is a change to all of them. Each is small in this lane (the lane reads public pages at low rates and keeps only text), and each should be a separate, reviewed change.
2. **The review was another model's work, in the same environment.** It could not reach any live host either. It did not look at deployment, secrets handling in Railway, or the database itself.
3. **No live read has ever happened.** Nine of the twelve source adapters were written from documentation or search excerpts (see 03-lead-sources). The first read on the production worker will show which of them need a fix.
4. **GitHub Actions cannot start jobs on this account (billing),** so none of this has been through the project's CI. The local runs are: 286 recruiting tests, 37 in the shared web-hazard ratchet (one of which flagged a comment in the recruiting reader, now reworded), the other tests that use the shared robots.txt code (all pass except five in `route-to-organization.test.ts`, which need a database that this environment does not have), the type check and the linter.
5. **The decision log has a hard end at 20,000 entries.** At the pace of a one-person side business that is years away; the page says so well before it, and an archive step would be a small separate change.
6. **Legal points** are unchanged and still need a lawyer (02-voice-and-compliance, last section).

## What the review found sound

The owner-or-admin check and the same-site check on the API; request size handling; that the server, not the browser, supplies the text of an approved message; that `__proto__` and `constructor` in JSON pollute nothing; that regions needing consent, placement and split fees cannot be switched on; that suppress, reply, edit and withdrawing the process each beat an earlier approval; that an unapproved process, personal addresses, a missing email footer and the default region all hold; a 49-address battery for role mailboxes; that the ledger needs proof plus confirmation; that every fetch goes through the guarded fetch; that there is no sending code and no unescaped HTML; that no XML entity expansion occurs; that the wording check and the reply classifier are linear at 600 KB; and that the worker and the page write separate rows.
