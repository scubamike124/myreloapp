### Corrections and extra findings

- README:50 "Write operations default to dry-run" is only true for the CLI wrapper (scripts/publish-book.mjs:4, :67 sets `dryRun: !live`). The REST handlers treat dryRun as true only when the body says so (index.ts:567, :581, :638), so a direct API call is live by default.
- "Never publish without explicit user confirmation" is prose for the AI agent (SKILL.md:123, :146; skills/publish-book/SKILL.md:22), not enforced in code. Code gate: `publish === true && !dryRun` (kdpPublish.ts:90-92, :383-385).
- Release schedule is changed without being asked: `setReleaseNow` clicks "release my book for sale now" or picks a date 14 days out (kdpCreateTitle.ts:74-138, fallback :106-136). It runs in every non-dry-run publish call (kdpPublish.ts:169-173) and in every metadata save (kdpMetadataUpdate.ts:536 is even before the dry-run check, :562, :664, :689), so editing a keyword can overwrite a deliberately scheduled release or pre-order date.
- Print option is overridden: the content step always selects Premium Colour ink and paper (`ensurePremiumColorSelected`, kdpContentUpdate.ts:281) and the recovery playbook does the same on a page-count error (kdpRecovery.ts:73-76, :184-194). This changes print cost and royalty and would be wrong for black-and-white coloring or low-content books.
- Free ISBN is always assigned in the content step (`assignFreeIsbn: true`, kdpContentUpdate.ts:279, :291).
- Previewer is auto-approved (kdpContentWait.ts:138-152) and the generative-AI checkbox is ticked if unchecked (kdpContentWait.ts:165-170). AI questionnaire answers exist only as `printSettings` (kdpContentUpdate.ts:31-45, fillBookContent.js:104-148), but the REST parser copies only interiorPath and coverPath (index.ts:660-665), so the API path cannot answer them.
- Adult-content question is answered "No" by default (kdpCategories.ts:239; kdpMetadataUpdate.ts:696) and language defaults to English in the wizard (kdpPublish.ts:151).
- It contains code ported from auto-kdp (comments at kdpContentWait.ts:45 and :100 and identical element ids) without the MIT notice, in a repo with no licence.
- Hard-coded macOS paths and the author's own title ids exist only in dev scripts (upload-staging-batch.ts:13, upload-staging-all.ts).

## 5. Overall recommendation

Do not install, run or integrate any of the three against the Amber One Press account as they stand: each conflicts with the Agents rules as described (stealth or user-agent spoofing, automation-hiding flags, Server Busy bypass), none supports an owner-driven remote sign-in from an iPhone, and all three set declarations for the owner by default (AI use, adult content or rights, depending on the tool); both TypeScript tools also assign a free ISBN, and the skill additionally forces Premium Colour and rewrites release dates. Keep the existing compliant flow. If anything is reused, take it from auto-kdp only, because it is the only one with a usable licence and tested pure logic: port the variable resolver, validation limits, description cleanup, marketplace table and retry/state runner with the MIT notice, and treat its Bookshelf selectors as facts to re-validate through the compliant flow (Playwright role/text locators, never `:contains()` or positional ids). From amazon-kdp-skill take ideas only (verify-after-save, a global request gap), rewritten independently because it has no licence. Discard kdp-autopublish.
