#### The site's own checkout: the live switch checklist (prepare only; the owner turns it on after approving final publish)

State as this process sees it: WEBSITE_SNAPSHOT_CHECKOUT off (pages are a 404) · WEBSITE_SNAPSHOT_LIVE_PAYMENTS not approved · Stripe key in this process's env: none (the checkout route reads STRIPE_SECRET_KEY from the vault, which this report cannot see).

1. Approve final publish: the page copy (the kit's long text), the sample report at /website-snapshot/sample, the terms at /website-snapshot/terms, and the support address buyers are told to write to.
2. Prerequisites, all on amber-hq-web: STRIPE_SECRET_KEY in the vault is the live key (sk_live_…); NEXT_PUBLIC_APP_URL (or NEXT_PUBLIC_SITE_URL) is the public origin, because the success and cancel pages are built from it; at least one Organization row exists (the checkout attaches each session to the first one); RESEND_INBOUND_DOMAIN is set if replies should reach Amber. No Stripe webhook is needed: the intake re-checks every payment with Stripe server-side.
3. Set WEBSITE_SNAPSHOT_CHECKOUT=true and redeploy. The pages and API routes appear. With a live key and nothing else, ordering shows "paused" with the support address: the checkout route refuses a live key until step 5, so this state is safe to look at.
4. Verify: GET /website-snapshot, /website-snapshot/sample and /website-snapshot/terms answer 200; POST /api/website-snapshot/checkout answers 503 "paused" (expected before step 5).
5. Set WEBSITE_SNAPSHOT_LIVE_PAYMENTS=true and redeploy. Live Checkout sessions are now created.
6. Verify without paying: POST /api/website-snapshot/checkout with your email returns ok, a Stripe URL and mode "live"; open the URL, see the $49 page, close it (nothing is charged until a card is entered and paid).
7. The first order: the buyer pays; /website-snapshot/thanks collects name, business, email and up to 5 public pages; the intake re-checks the payment with Stripe and saves the order as pending_review on web's volume; you run `npm run website-snapshot -- --client "<business>" --pdf --out-dir <dir> <urls>`, review the PDF against the safe-to-send checklist, and send it within 2 business days. The revenue dashboard counts the live paid order.
8. Pause or rollback: WEBSITE_SNAPSHOT_LIVE_PAYMENTS=false pauses ordering (pages stay); WEBSITE_SNAPSHOT_CHECKOUT=false hides everything again. Refunds are made by hand in the Stripe dashboard under the refund rule in the terms.
